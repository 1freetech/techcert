## Publishing rules

- Verify live WordPress numbering and GitHub duplicates before every lesson.
- Write lessons as formal instruction/lecture material, not author-to-reader conversation.
- Begin complex lessons with an Elementary Overview and end with an Elementary Conclusion written as clear, accurate Wikipedia-style explanations for an intelligent 10-year-old reader.
- Do not use explanatory text boxes or arrow-style procedure/sequence diagrams.
- Code blocks are reserved for actual commands and command output examples.
- Include one unique relevant 1200×630 featured cover, use a realistic or other approved rich visual style rather than minimalist art, and do not reuse the cover in the body.
- Every substantive paragraph must have at least one directly relevant, verified, playable instructional video; each video URL may appear only once and duplicate video embeds are prohibited.
- Prefer official manufacturers, universities, standards bodies, technical training organizations, respected engineering educators, RealPars, and saved playlists; do not use filler videos.
- Make BitcoinVersus.Tech function like an internal wiki: naturally hyperlink key commands, hardware, software, protocols, companies, and concepts to the most specific relevant prior BitcoinVersus.Tech article whenever one exists.
- Link earlier Linux lessons when they materially support the topic.
- Archive the exact final Gutenberg source to BitcoinVersus, TechCert, and Open CERT and read all three copies back before advancing rotation.
