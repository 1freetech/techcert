<!-- wp:paragraph --><p>VLANs separate Layer 2 broadcast domains, which improves organization and control but also prevents devices in different VLANs from communicating directly at Layer 2. When VLAN 10 must communicate with VLAN 20, a Layer 3 device must route packets between the two IP networks. This process is called <strong>inter-VLAN routing</strong>. This lesson follows <a href="https://bitcoinversus.tech/2026/10/09/osntc-022-vlan-trunking-802-1q-tagged-frames-native-vlans-allowed-vlans-verification/">OSNTC.022: VLAN Trunking and 802.1Q</a> and builds on <a href="https://bitcoinversus.tech/2026/09/30/osntc-004-vlan-basics/">OSNTC.004: VLAN Basics</a>, <a href="https://bitcoinversus.tech/2026/10/03/osntc-013-router-basics/">OSNTC.013: Router Basics</a>, and <a href="https://bitcoinversus.tech/2026/10/09/osntc-021-troubleshooting-switch-ports-link-status-errors-vlans/">OSNTC.021: Troubleshooting Switch Ports</a>.</p><!-- /wp:paragraph -->
<!-- wp:heading --><h2 class="wp-block-heading">ELEMENTARY OVERVIEW</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p>A host in VLAN 10 can communicate directly with another host in VLAN 10 because both devices share the same Layer 2 broadcast domain. A host in VLAN 10 cannot directly deliver an Ethernet frame to a host in VLAN 20 as though both were in the same LAN. Instead, the source host sends the packet to its default gateway. The gateway routes the packet from the VLAN 10 IP network into the VLAN 20 IP network and then forwards it toward the destination.</p><!-- /wp:paragraph -->
<!-- wp:paragraph --><p>Inter-VLAN routing can be implemented in several ways. A traditional router can use separate physical interfaces for separate VLANs. A router-on-a-stick design uses one physical router interface divided into logical subinterfaces, with an 802.1Q trunk carrying multiple VLANs to the router. A Layer 3 switch can create switch virtual interfaces (SVIs) and route between VLANs internally at switching hardware speeds.</p><!-- /wp:paragraph -->

<!-- wp:heading --><h2 class="wp-block-heading">WHY A DEFAULT GATEWAY IS REQUIRED</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p>Every IP host determines whether a destination is local or remote by comparing the destination address with its own address and subnet mask or prefix length. If the destination is local, the host resolves the destination's Layer 2 address and sends directly. If the destination is remote, the host sends the packet to its configured default gateway. The gateway must have a Layer 3 interface in the source VLAN and a route toward the destination network.</p><!-- /wp:paragraph -->
<!-- wp:paragraph --><p>For example, VLAN 10 might use network 192.168.10.0/24 with gateway 192.168.10.1, while VLAN 20 uses 192.168.20.0/24 with gateway 192.168.20.1. A host at 192.168.10.50 sends traffic for 192.168.20.50 to 192.168.10.1. The routing device removes the incoming Layer 2 frame, examines the IP packet, selects the connected VLAN 20 route, builds a new Layer 2 frame for VLAN 20, and forwards the packet toward the destination.</p><!-- /wp:paragraph -->
<!-- wp:heading --><h2 class="wp-block-heading">ROUTER-ON-A-STICK</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p>Router-on-a-stick uses one physical Ethernet connection between a switch and a router. The switch-facing port is an 802.1Q trunk. On the router, logical subinterfaces divide the physical interface into separate Layer 3 interfaces. Each subinterface is associated with a VLAN tag and receives an IP address that normally becomes the default gateway for that VLAN.</p><!-- /wp:paragraph -->
<!-- wp:paragraph --><p>A common Cisco IOS-style example uses a physical interface such as <code>GigabitEthernet0/0</code> and creates subinterfaces such as <code>GigabitEthernet0/0.10</code> and <code>GigabitEthernet0/0.20</code>. Each subinterface is configured with 802.1Q encapsulation for its VLAN and with the appropriate gateway IP address. Exact command syntax varies by router platform and software release, so production configuration should be checked against the platform documentation.</p><!-- /wp:paragraph -->
<!-- wp:paragraph --><p>Router-on-a-stick is easy to understand and useful in smaller environments, labs, and branch networks. Its main limitation is that all routed VLAN traffic shares one physical router link, so bandwidth and redundancy requirements can eventually favor a Layer 3 switching design.</p><!-- /wp:paragraph -->

<!-- wp:heading --><h2 class="wp-block-heading">LAYER 3 SWITCHING AND SVIS</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p>A multilayer or Layer 3 switch can perform routing in addition to Ethernet switching. Instead of sending every inter-VLAN packet to an external router, the switch can create a <strong>switch virtual interface</strong> for each VLAN that requires Layer 3 connectivity. Cisco describes an SVI as a VLAN of switch ports represented as one interface to the routing function.</p><!-- /wp:paragraph -->
<!-- wp:paragraph --><p>For example, an SVI named <code>interface Vlan10</code> might use IP address 192.168.10.1/24, and <code>interface Vlan20</code> might use 192.168.20.1/24. Hosts in VLAN 10 use the VLAN 10 SVI as their gateway; hosts in VLAN 20 use the VLAN 20 SVI. When Layer 3 routing is enabled on the switch, it can route between those connected networks directly.</p><!-- /wp:paragraph -->
<!-- wp:paragraph --><p>An SVI is not a physical port. It is a logical Layer 3 interface associated with a VLAN. Physical access ports place endpoints into the VLAN, trunk ports transport the VLAN between devices, and the SVI provides the Layer 3 gateway for that VLAN. All three concepts work together.</p><!-- /wp:paragraph -->
<!-- wp:heading --><h2 class="wp-block-heading">ROUTER-ON-A-STICK VS. LAYER 3 SWITCH</h2><!-- /wp:heading -->
<!-- wp:list --><ul><li><strong>Router-on-a-stick:</strong> one router physical interface, multiple tagged subinterfaces, switch-to-router trunk, simple and common in labs or smaller networks.</li><li><strong>Layer 3 switch:</strong> VLAN gateways live on SVIs inside the switch, routing occurs locally, and inter-VLAN forwarding can scale efficiently.</li><li><strong>Separate router interfaces:</strong> one physical router interface per VLAN, simple conceptually but inefficient when many VLANs are required.</li></ul><!-- /wp:list -->
<!-- wp:heading --><h2 class="wp-block-heading">COMMON CISCO IOS-STYLE VERIFICATION</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p>Begin with read-only verification. On the switch, <code>show vlan brief</code> confirms that the expected VLANs exist. <code>show interfaces trunk</code> confirms that the router or upstream switch link is trunking and carrying the required VLANs. <code>show ip interface brief</code> displays routed interfaces and SVI status. <code>show ip route</code> confirms that the routing table contains connected VLAN networks and any required upstream routes.</p><!-- /wp:paragraph -->
<!-- wp:paragraph --><p>On a router-on-a-stick design, verify that the physical interface is up, the expected subinterfaces exist, each subinterface has the correct VLAN encapsulation and gateway address, and the connected switch trunk allows those VLANs. On a Layer 3 switch, verify that the SVI is configured, the VLAN exists, at least one required Layer 2 path for the VLAN is active where the platform requires it, and Layer 3 routing is enabled.</p><!-- /wp:paragraph -->
<!-- wp:heading --><h2 class="wp-block-heading">COMMON FAILURE PATTERNS</h2><!-- /wp:heading -->
<!-- wp:list --><ul><li><strong>Host can reach same-VLAN peers but not another VLAN:</strong> verify the host's default gateway, gateway interface state, and routing table.</li><li><strong>One VLAN cannot reach the router:</strong> verify that the VLAN is allowed on the trunk and that the router subinterface uses the correct 802.1Q VLAN ID.</li><li><strong>SVI is down:</strong> verify the VLAN exists and that the switch has an active Layer 2 port or trunk carrying that VLAN according to platform behavior.</li><li><strong>Correct gateway but no remote connectivity:</strong> verify the routing device has a route toward the destination and that return routing exists.</li><li><strong>Some VLANs work and one does not:</strong> compare that VLAN's addressing, allowed-trunk list, gateway interface, and spanning-tree state with the working VLANs.</li><li><strong>Wrong subnet mask or prefix:</strong> the host may incorrectly classify a remote destination as local or vice versa.</li></ul><!-- /wp:list -->
<!-- wp:heading --><h2 class="wp-block-heading">PACKET WALK: VLAN 10 TO VLAN 20</h2><!-- /wp:heading -->
<!-- wp:list {"ordered":true} --><ol><li>Host A in VLAN 10 determines that Host B's VLAN 20 IP address is remote.</li><li>Host A sends the packet to the MAC address of its VLAN 10 default gateway.</li><li>The switch forwards the frame toward the routing device while preserving VLAN 10 membership.</li><li>The router or Layer 3 switch removes the incoming Ethernet header and examines the IP destination.</li><li>The routing table selects the connected VLAN 20 network.</li><li>The routing device resolves the Layer 2 destination in VLAN 20 if necessary.</li><li>A new Ethernet frame is created for VLAN 20.</li><li>The switch forwards the frame through VLAN 20 toward Host B.</li><li>The return packet follows the same Layer 3 principle in the opposite direction.</li></ol><!-- /wp:list -->
<!-- wp:heading --><h2 class="wp-block-heading">PRACTICAL LAB</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p>Build a lab with VLAN 10 and VLAN 20. Assign one host to each VLAN and give each VLAN a different IPv4 subnet. First confirm that the two hosts cannot communicate without Layer 3 routing. Then configure either router-on-a-stick or Layer 3 switch SVIs. Set each host's default gateway to the corresponding router subinterface or SVI. Verify same-VLAN connectivity, gateway reachability, and finally inter-VLAN reachability.</p><!-- /wp:paragraph -->
<!-- wp:paragraph --><p>After successful routing, intentionally remove VLAN 20 from the trunk or change one host's default gateway to an incorrect address. Record the failure symptoms, then restore the correct configuration and compare the verification output. Perform changes only in a lab or approved maintenance environment.</p><!-- /wp:paragraph -->
<!-- wp:heading --><h2 class="wp-block-heading">TECHNICIAN TROUBLESHOOTING WORKFLOW</h2><!-- /wp:heading -->
<!-- wp:list {"ordered":true} --><ol><li>Confirm the source host's IP address, subnet mask or prefix, and default gateway.</li><li>Confirm the destination host's IP address, subnet mask or prefix, and default gateway.</li><li>Verify that both VLANs exist.</li><li>Verify access-port VLAN assignments.</li><li>Verify trunk status and allowed VLANs.</li><li>Verify router subinterfaces or Layer 3 switch SVIs.</li><li>Verify gateway interface state.</li><li>Verify connected routes and any required static or dynamic routes.</li><li>Use ping in stages: local host to gateway, gateway to destination VLAN, then end to end.</li><li>Check ARP or neighbor information where appropriate.</li><li>Make the smallest approved correction.</li><li>Re-run verification and document the final working state.</li></ol><!-- /wp:list -->
<!-- wp:heading --><h2 class="wp-block-heading">KNOWLEDGE CHECK</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p><strong>1.</strong> Why can two different VLANs not communicate directly at Layer 2? <strong>2.</strong> What role does the default gateway play? <strong>3.</strong> What is router-on-a-stick? <strong>4.</strong> What is an SVI? <strong>5.</strong> Why must the switch trunk carry the VLAN used by a router subinterface? <strong>6.</strong> Which command commonly displays the routing table on Cisco IOS-style devices?</p><!-- /wp:paragraph -->
<!-- wp:heading --><h2 class="wp-block-heading">ANSWER GUIDE</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p><strong>1.</strong> Each VLAN is a separate Layer 2 broadcast domain, so communication between them requires Layer 3 routing. <strong>2.</strong> It receives packets destined for remote IP networks and routes them onward. <strong>3.</strong> It is a design where one physical router link carries multiple VLANs using 802.1Q-tagged subinterfaces. <strong>4.</strong> It is a logical Layer 3 interface representing a VLAN on a multilayer switch. <strong>5.</strong> Without that VLAN on the trunk, tagged traffic for the subinterface cannot reach the router. <strong>6.</strong> <code>show ip route</code>.</p><!-- /wp:paragraph -->
<!-- wp:heading --><h2 class="wp-block-heading">CONCLUSION</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p>VLANs intentionally separate Layer 2 traffic, so communication between VLANs requires a Layer 3 gateway. Router-on-a-stick provides that gateway with tagged subinterfaces over one trunk, while Layer 3 switches provide gateways through SVIs and route internally. The technician's job is to verify addressing, VLAN membership, trunking, gateway interfaces, and routing in a disciplined order. When those layers are checked one by one, inter-VLAN routing failures become much easier to isolate.</p><!-- /wp:paragraph -->
