Creating a Fixed-Length Array

A declaration such as int[] values; names a variable that can refer to an array; it does not create the array. values = new int[4]; allocates an array with four integer slots, initially all zero. The initializer syntax int[] values = {4, 7, 9, 12}; creates and fills the array in one expression. Its length is values.length, a field—not a method call such as values.length(). Once an array is allocated, its length cannot be resized; a new array can be created and references reassigned.

Elements are accessed with square brackets. For four values, the valid indexes are 0, 1, 2, and 3. Index 0 holds 4 and index 2 holds 9. Attempting index 4 or index -1 throws an ArrayIndexOutOfBoundsException during execution. Iterating with for (int i = 0; i < values.length; i++) prevents a common off-by-one error, provided that the array reference is non-null.

An enhanced for (int value : values) loop visits each element without exposing its index. Use it when the current position does not matter. An indexed loop remains useful when examining neighboring elements, assigning to a particular element, or recording an element's position. Java array elements of reference types default to null when initialized with new; using one without first assigning a suitable object can cause a NullPointerException.

Copying an Array Is Not the Same as Aliasing

Assignment such as int[] alias = values; copies the reference to an array, not its entire contents. Mutating an element using either variable changes the same underlying object. To create an independent one-dimensional array of integers, Arrays.copyOf(values, values.length) allocates a new array and copies the element values. After copy[1] = 20, the copied array is [4, 20, 9, 12], while the original remains [4, 7, 9, 12].

The distinction depends on element type. Copying an array of primitive values copies those primitive values. Copying an array of references copies references to the same underlying objects: the result is a shallow copy, not a deep clone of all referenced objects. This matters for arrays of mutable custom objects. Refer to Oracle's Java SE 21 Arrays class documentation for exact method semantics.

Half-Open Ranges and Standard Array Utilities

The call Arrays.copyOfRange(values, 1, 3) copies indexes 1 and 2, yielding [7, 9]. It uses the half-open interval [from, to): the first index is included and the last index is excluded. The returned array has length to - from. For some primitive overloads, a valid to beyond the source length pads with a primitive zero value; the method is not a universal substitute for strict range validation.

Arrays.toString(values) returns a human-readable representation of a one-dimensional array. Arrays.equals(a, b) compares corresponding primitive elements, unlike a == b, which compares array references. Arrays.sort(values) sorts an array in place, so use a copy to preserve the original order. Arrays.binarySearch requires the searched range to be sorted according to its documented ordering; a matching element's index is returned, while a missing element yields a negative result encoding the insertion point. Binary search on an unsorted array is not a reliable way to find an element.

Arrays of Arrays and Unequal Row Lengths

Java supports an int[][] value as an array whose elements are references to int[] row arrays. The example {{4, 7}, {9}, {12, 15, 18}} has row lengths 2, 1, and 3. It is therefore called jagged, or irregular. It is not necessary for each row to have equal length. When iterating rows, use rows[i].length after ensuring the row is non-null, rather than assuming the first row's length applies to every row.

For a rectangular numeric grid, it can be useful to enforce equal row lengths as an application-level contract, but the Java language does not require the property. These nested arrays are distinct objects; clone() or Arrays.copyOf() of the outer array does not deep-copy every inner array.

Troubleshooting, Safety, and Performance Boundaries

  • ArrayIndexOutOfBoundsException: an index is negative or at least the array's length. Print or log the index and length in a development environment, then correct the loop condition or input validation.
  • NullPointerException: the array variable or a referenced element is null. Initialize before use and validate external inputs rather than assume non-null values.
  • ArrayStoreException: an array with a reference-element runtime type receives an incompatible object. Arrays are covariant in Java; such stores may compile through a broader reference type but fail at runtime.
  • Unexpected changes: determine whether two variables alias one array or whether a shallow copy still shares mutable elements.
  • Incorrect search results: sort the searched range before calling Arrays.binarySearch and interpret a negative result as an insertion-point code, not necessarily an ordinary -1.
  • Overflow: a sum of many integers can exceed 32-bit range. The exercise uses Math.addExact to fail visibly; a production system may need a long, exact arithmetic, or explicit bounds.

Do not convert out-of-range access into blanket exception suppression. It is usually better to validate an untrusted position before reading the array and to treat impossible internal indexes as programming defects. Check input sizes before allocating large arrays to prevent resource exhaustion. A fixed number of elements does not imply a fixed memory footprint for arrays of reference types or nested arrays. This lesson measures values and behavior only, not allocation overhead, execution timing, or garbage-collector performance.

Knowledge Check and Answer Key

  1. What is the first legal index of a Java array? Zero.
  2. What is the last legal index when the array length is 4? Three.
  3. Does an array resize when assigned a longer sequence? No. Its length is fixed; create another array.
  4. Does int[] b = a make an independent copy? No. It assigns another reference to the same array object.
  5. Does Arrays.copyOf deep-copy referenced objects? No. It creates another array and copies element values, which can be references.
  6. What does Arrays.copyOfRange(a, 1, 3) include? Indexes 1 and 2, with 3 excluded.
  7. Why can jagged arrays have different row lengths? Each row is a separate array and may have its own length.
  8. What must be true before calling Arrays.binarySearch? The searched range must be sorted according to the relevant ordering.

Conclusion

Java arrays are fixed-length objects with predictable typed element access and runtime-checked indexes. The most important beginner distinctions are zero-based positions, the difference between an alias and a real copy, and the proper treatment of array lengths and bounds. Combining verified examples with explicit error tests prepares students for collections, data processing, sorting, and safe application input handling.
