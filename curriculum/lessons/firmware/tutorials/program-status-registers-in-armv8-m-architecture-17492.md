<!-- wp:paragraph -->
<p>The <strong>Program Status Registers, or PSRs, in Armv8-M</strong> store information about <a href="https://bitcoinversus.tech/2025/03/07/cpu-architecture-and-microarchitecture-explained/">the processor’s</a> current execution state, arithmetic results and active exception. </p>
<!-- /wp:paragraph -->

<!-- wp:paragraph -->
<p>Armv8-M organizes this information into three primary views: the <strong>Application Program Status Register (APSR)</strong>, <strong>Interrupt Program Status Register (IPSR)</strong> and <strong>Execution Program Status Register (EPSR)</strong>. </p>
<!-- /wp:paragraph -->

<!-- wp:paragraph -->
<p>These can also be viewed together through the combined <strong>xPSR</strong> representation. Together, the registers allow the processor and system software to track condition flags, exception status and execution-state information during normal program execution and interrupt handling.</p>
<!-- /wp:paragraph -->

<!-- wp:paragraph -->
<p>The <strong>APSR</strong> primarily contains condition flags generated by arithmetic and logical operations, including the <strong>N, Z, C and V flags</strong> for negative, zero, carry and overflow conditions, along with additional status information on supporting architecture extensions. These flags are important for conditional operations and evaluating the results of calculations. </p>
<!-- /wp:paragraph -->

<!-- wp:paragraph -->
<p>The <strong>IPSR</strong>, by comparison, identifies the currently executing exception or interrupt; a value representing no active exception corresponds to normal Thread-mode execution, while other values identify active system or external exceptions. </p>
<!-- /wp:paragraph -->

<!-- wp:paragraph -->
<p>This makes the IPSR particularly useful to firmware, RTOS kernels and low-level debugging tools that need to determine whether code is executing normally or inside an exception handler.</p>
<!-- /wp:paragraph -->

<!-- wp:paragraph -->
<p>The <strong>EPSR</strong> contains information associated with the processor’s execution state, including state used by the T32 instruction environment and instruction-continuation or conditional-execution mechanisms. </p>
<!-- /wp:paragraph -->

<!-- wp:paragraph -->
<p>Software typically encounters these status fields through PSR-related register views rather than treating the EPSR as a conventional general-purpose register. </p>
<!-- /wp:paragraph -->

<!-- wp:paragraph -->
<p>Collectively, the APSR, IPSR and EPSR provide a compact snapshot of what an Armv8-M processor is doing at a particular moment: <strong>the APSR describes the result state, the IPSR identifies the exception state, and the EPSR tracks execution state</strong>. </p>
<!-- /wp:paragraph -->

<!-- wp:paragraph -->
<p>This makes the Program Status Registers essential to embedded debugging, exception handling, context switching and low-level firmware development on Armv8-M processors such as Cortex-M23 and Cortex-M33.</p>
<!-- /wp:paragraph -->
