A digital-to-analog converter (DAC) changes numerical codes into analog voltage or current. Embedded systems use DACs for reference signals, calibration, audio and waveform generation. A correct register value does not guarantee a correct voltage: the reference, output loading and timing also matter.

Prerequisites

Review ADC diagnostics, timer and PWM diagnostics, clock source diagnostics and DMA buffering.

Learning objectives

  • Explain DAC resolution and reference-voltage dependence.
  • Calculate expected voltage and waveform repetition frequency.
  • Distinguish settling time, output loading and reference errors.
  • Interpret timer-trigger and DMA-underrun symptoms.
  • Perform safe, read-only diagnostic verification and document results.

Code-to-voltage conversion

A 12-bit DAC accepts 4096 distinct codes, numbered 0 through 4095. For an ideal unipolar converter with a 3.3 V reference and a 4096-denominator transfer function, one least significant bit (LSB) equals 3.3/4096 ≈ 0.806 mV. Code 2048 gives 1.65 V. The maximum code gives approximately 3.2992 V in that ideal model. Consult the exact device's specified transfer function; some documentation uses a full-scale endpoint convention with denominator 4095. Real output offset, gain error and buffer headroom limit accuracy.

Timing and waveform frequency

A timer can trigger conversion of successive codes from a waveform table. DMA can transfer the codes without requiring software to write every sample. For a repeating table containing N samples per period, waveform frequency equals sample rate divided by N. A 100-sample table updated at 20,000 samples/s produces 200 Hz, with 50 μs between updates. The STMicroelectronics DAC guide describes buffered and triggered output modes.

Settling and output loading

Settling time specifies how long the analog output takes to remain within a stated error band after a code change. It depends on step size, buffer mode and load. A conversion trigger can arrive before the voltage has settled, distorting the intended waveform. An unexpectedly low output may result from a heavy resistive load, excessive capacitance or insufficient output headroom. Compare observed conditions against the exact MCU datasheet, not a different STM32 family. Measure the reference as well as output and distinguish a constant offset from a proportional gain error.

Fault isolation

For a static output, inspect the configured pin, DAC channel enable, reference and commanded code using an approved debug method. For a repeating waveform, compare measured frequency with the timer clock, prescaler, period and table length. Stale or discontinuous samples can result from incorrect DMA routing, data width, buffer length or underrun. Check applicable hardware error flags and preserve the original fault state before restarting. A debugger halt can change timing; a readout from an actively running peripheral may also have side effects. Follow the device manual.

Safe verification

Use a disconnected, low-voltage training board or supplied measurements, not production control hardware. Verify the permitted pin voltage, common reference and instrument input impedance before connecting a meter or oscilloscope. Never attach an earth-referenced probe to an unknown potential. Compare static low, mid and high codes within approved limits, then measure a safe waveform frequency and amplitude. Record board revision, firmware version, reference voltage, commanded code, measured output, load, instrument settings and applicable tolerances. Escalate faults rather than changing live firmware or protection settings.

Exercises and answer key

  • For the ideal 3.3 V, 12-bit model, find code 1024 voltage. Answer: 0.825 V.
  • A 64-sample table runs at 32 kHz. Find output frequency. Answer: 500 Hz.
  • Why might a correct code produce low voltage? Answer: reference error, loading, headroom or gain error.
  • A waveform intermittently holds its previous sample. What evidence matters? Answer: trigger timing, DMA status, buffer configuration and underrun flags.
