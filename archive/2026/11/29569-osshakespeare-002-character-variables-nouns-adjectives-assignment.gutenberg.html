Learning Objectives and Prerequisites

The Shakespeare Programming Language (SPL) treats recognized Shakespearean characters as signed-integer variables. Learners will declare a character, distinguish a speaker from the character receiving a value, calculate poetic constants, and inspect numeric output. Review OSShakespeare.001 — Program Structure before continuing. The same underlying ideas are familiar from PowerShell variables and C# variables and numeric types, although SPL uses theatrical language rather than an equals sign.

Elementary Overview

Imagine two actors standing on an empty stage. One delivers a line, while the other receives a message. In SPL, the speaker is a character name followed by a colon. The character being addressed is the other variable currently on stage. A compliment or insult can assign that variable an integer. Words such as a rose and a pig are not arbitrary literary decoration: the language assigns them numeric meanings.

An SPL play begins with a title, character declarations, an Act and Scene, and stage directions. The prior lesson covered that structure. The new skill is following a value from written words to the recipient’s stored number. Understanding that distinction prevents the most common beginner error: assuming the speaker is the variable being changed.

Declaring the Variables

A character declaration uses a recognized Shakespearean name followed by a descriptive phrase. The runtime stores a signed integer for each declared character, and the descriptive phrase is ignored by the language parser. For example, the following declarations create two distinct integer variables:

Hamlet, a thoughtful prince. Juliet, a careful observer.

The declared names must belong to the implementation’s recognized list of Shakespeare characters; inventing a random fictional name is not guaranteed to compile. An SPL description is not a type annotation or an initial value. It exists primarily to make the source resemble a stage play. The storage is associated with the actual character name.

The Stage Decides Who Receives a Value

The speaker and recipient must be on stage in a valid arrangement. With Hamlet and Juliet both present, a line attributed to Juliet directs second-person language toward Hamlet. The line below asks Hamlet to take the numeric value represented by a King:

[Enter Hamlet and Juliet] Juliet: Thou art a King. Open your heart.

The original language specification defines a positive noun such as King as the value 1. The line changes Hamlet’s integer variable, and Open your heart prints its numeric value. By contrast, Speak your mind interprets that integer as a character code. Both output instructions operate on the person being addressed, not on the speaker.

Why Nouns and Adjectives Become Numbers

A positive or neutral noun contributes +1, while a negative noun contributes −1. Every adjective preceding a noun doubles the magnitude. A positive noun with two adjectives represents +4; a negative noun with two adjectives represents −4. No power operator is typed explicitly because the grammar makes an adjective act as a multiplication by two.

Compute Positive and Negative Constants

The lexical examples below illustrate the signed powers of two defined by the original SPL language report. Each adjective doubles the magnitude contributed by the noun. The values are mathematical interpretations of SPL phrases, not ordinary English-language sentiment scores:

a rose = +1 a lovely rose = +2 a lovely sweet rose = +4 a pig = -1 a rotten pig = -2 a rotten smelly pig = -4

The original language specification assigns positive value to a flower or rose and negative value to a pig. Extra adjectives multiply the absolute value by two, regardless of whether they sound positive or negative. A programmer can form larger values through arithmetic expressions in dialogue. Some editions or alternative interpreters have slightly different accepted word lists, so always consult the implementation’s vocabulary before inventing poetic constants.

Assignments Operate on the Listener

A sentence addressed to the other character on stage assigns a number to that character. With Juliet speaking to Hamlet, Thou art a lovely rose. means Hamlet receives positive two. A later assignment replaces the current value. Numeric output is requested separately, as shown in the following dialogue:

Juliet: Thou art a lovely rose. Open your heart. Thou art a rotten pig. Open your heart.

The two output operations request the signed numbers +2 and −1, respectively. An interpreter may print the numbers consecutively rather than adding separators, so a captured terminal output can look different from a list of separately evaluated values. The numerical interpretation follows the original grammar; exact terminal formatting has not been runtime-tested here.

Arithmetic Can Reuse a Character’s Value

The pronouns thyself and yourself refer to the listener’s current value within an assignment. A sum can add another constant without changing the speaker’s stored value. Starting from Hamlet = 2, the following line updates Hamlet to three:

Juliet: Thou art the sum of thyself and a flower. Open your heart.

A new assignment is not an incremental modification unless its expression uses the old value. The earlier phrase Thou art a King. simply replaces whatever Hamlet held with +1. A sum using thyself instead reads the previous value, adds another expression, and stores the result back into the same listener variable.

Practical Lab — A Small Play That Counts

Save an original example as character_values.spl in a disposable project directory. The program has one Act, one Scene, two characters, and two numeric output operations. Juliet speaks, Hamlet receives the values, and the arithmetic expression reuses Hamlet’s previous value. All required context is included in the complete source file:

A Small Reckoning. Hamlet, a thoughtful prince. Juliet, a careful observer. Act I: The Reckoning. Scene I: Counting in Words. [Enter Hamlet and Juliet] Juliet: Thou art a lovely rose. Open your heart. Thou art the sum of thyself and a flower. Open your heart. [Exeunt]

The expected numeric outputs are two followed by three. Since SPL numeric output does not necessarily insert a separator between successive values, a reader might see 23 rather than two lines. Do not interpret that possible display as the single value twenty-three. The lesson example is source-reviewed against the original SPL documentation, but has not been executed through an installed interpreter during publication.

Using a Modern Interpreter

The community-maintained shakespearelang Python implementation provides a command-line runner and debugger. For an isolated environment, create a virtual environment and activate it before installing the package. Installation may vary by operating system and Python version. Use the commands below in a disposable development environment, not on an unfamiliar production host:

python -m venv .venv # Activate .venv using the steps for your operating system. python -m pip install shakespearelang shakespeare run character_values.spl

The commands assume an environment where the installed shakespeare command is available on the active PATH. To observe assignments and stage state, consult the interpreter’s documented debugger. A command shown in an educational lesson is not evidence that it successfully ran in the publishing environment.

Common Errors and Diagnostics

Troubleshooting starts by identifying which character currently speaks and which character receives the assignment. A well-formed play may still produce unexpected results if a value is assigned to the wrong listener, a poetic constant has an unexpected sign, or a noun is not part of the interpreter’s grammar. Check the following failures in a safe test environment rather than changing a production system:

An undeclared or unrecognized character name may fail during parsing. Use supported names such as Hamlet, Romeo, or Juliet and declare them before their first entrance. If a third character is on stage, a second-person assignment becomes ambiguous; keep introductory exercises limited to two characters. A description after a character name is ignored by the original parser and cannot initialize the variable. Use Open your heart for numeric output instead of the character-oriented Speak your mind. Finally, remember that an ordinary assignment replaces the current number, while an expression involving thyself can reuse the existing value.

Practice and Knowledge Check

Replace a lovely rose with a lovely sweet rose and predict the first value before running the play. It becomes four because two adjectives double positive one twice. The final value becomes five after adding a flower. Next, change the first noun to a pig and explain its negative sign. Finally, switch the speaker and listener and identify which character variable receives the assignment.

What does a character store? A signed integer, with a stack available elsewhere in the language. Does Juliet update herself while saying Thou art a King to Hamlet? No, Hamlet is the listener and receives +1. What does each adjective do? It doubles the magnitude of a noun constant. What makes thyself useful? It provides the current listener value so an expression can calculate a new one.

Why the Language Matters

The Shakespeare Programming Language is a deliberately experimental language showing that variables, numbers, and assignments need not be written using ordinary programming syntax. The unrelated Chef esoteric programming language uses culinary metaphors rather than theatrical dialogue. A wider history of programming languages helps explain why practical languages emphasize compact syntax, tooling, and maintainability. SPL remains valuable for understanding how tokenization and parsing can assign precise computational meaning to surprising surface forms.

Elementary Conclusion

A Shakespeare Programming Language character is an integer variable, and theatrical dialogue can be an assignment. Nouns represent positive or negative one, adjectives repeatedly double the magnitude, and arithmetic expressions combine those values into larger numbers. The speaker generally directs a second-person assignment to the other character on stage. Once the listener and its current value are clear, later lessons on dialogue syntax, stacks, and control flow become much easier to follow.
