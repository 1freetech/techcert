A method is a named group of Java statements that performs a defined task. Methods let programs reuse operations, accept inputs through parameters, and return calculated results. Java also permits several methods to share one name when their parameter lists differ. Correct method design depends on an accurate understanding of Java's pass-by-value argument rules, especially when arrays or objects are passed into functions.

The topic follows our Java arrays reference. Earlier lessons cover String values and immutability, control flow, primitive types, and compiling Java with the JDK. The official Java methods reference supplies the language definitions.

Elementary Overview

Think of a method as a kitchen recipe. A recipe has a name, may receive ingredients, and can produce a result. A method called add can accept two numbers and return their sum. A second method named add can accept decimal numbers. The computer chooses between them using the input types. When the caller gives a method an array, both can see the same collection of elements, even though Java passes a copy of the array reference rather than handing over the caller's variable.

Method Declarations and Signatures

A normal declaration identifies the method's return type, name, parameter list, and code body. Optional modifiers, including public, private, and static, specify access and whether the operation belongs to a class rather than an instance. The example static int add(int a, int b) returns an integer and accepts two integer parameters. The parentheses remain present even when a method accepts no parameters.

In Java terminology, a method's signature consists of its name and parameter types, not its return type. Parameter names improve readability but do not make distinct overloads. Two declarations differing only in their result type are not legal overloads. The return type void means that no value is returned, although a return; statement may end a void method early. For a non-void method, every normally completing route must return a compatible value or the compiler reports an error.

Parameters, Arguments, and Returned Results

A parameter is a local variable declared inside a method's parentheses; an argument is the value supplied by its caller. For add(3, 4), the values 3 and 4 are arguments copied into parameters a and b. A returned result may be stored, printed, or used in another expression. Returning a value is different from printing one, because printing only writes to an output stream and does not give the caller a computed result.

Method contracts should also say what happens with invalid input. The demonstration's sum method rejects null arrays using IllegalArgumentException. Its integer arithmetic uses Math.addExact to make overflow explicit through ArithmeticException, rather than silently accepting wraparound. Such choices illustrate one policy, not a universal requirement for every mathematical function. The official parameters guide covers argument matching and variable-length argument lists.

Overloading and Variable-Length Arguments

The two add declarations accept either two int values or two double values. The compiler examines the call's applicable argument types to choose the appropriate overload. As a rule, prefer a small number of clear overloads; conversion and overloaded names can become ambiguous in larger APIs. Changing only the return type cannot resolve a call, because the return type is not enough to distinguish signatures.

The syntax int... values declares a varargs parameter. Callers may pass zero, one, or several integers, and the method receives an array. Only the final parameter may use the varargs form. The method countPositive(-2, 0, 3, 7) counts two positive numbers. Varargs are convenient for small APIs, but callers should still understand how empty input is handled.

Pass-by-Value: Primitives and Shared Objects

Java always passes arguments by value. Passing an int copies its numerical value, so assigning a new number to the parameter does not change the caller's variable. Passing an array copies the reference value. Both reference copies point to the same array object, so modifying an element is visible to the caller. Reassigning the method's local parameter to a newly allocated array, however, does not redirect the caller's variable. Oracle documents the distinction in its parameter-passing tutorial.

Consider the earlier array aliasing example. Two Java variables can hold references to the same array, but neither variable is identical to the array itself. Calling changeFirst(readings) writes into shared storage; calling replaceArray(readings) changes only the local parameter's reference. As a result, the original caller still sees the array with its modified first element.

Complete Executable Java Example

Save the following source as MethodLab.java. The example includes overloads, typed returns, a void method, variable-length arguments, ordinary input validation, and assertions implemented without external libraries. Every tested operation runs locally with a JDK:

public final class MethodLab {
    private MethodLab() { }

    static int add(int a, int b) {
        return Math.addExact(a, b);
    }

    static double add(double a, double b) {
        return a + b;
    }

    static String describe(String name, int count) {
        return name + ": " + count;
    }

    static int sum(int[] values) {
        if (values == null) {
            throw new IllegalArgumentException("values must not be null");
        }
        int total = 0;
        for (int value : values) {
            total = Math.addExact(total, value);
        }
        return total;
    }

    static void changeNumber(int value) {
        value = 99;
    }

    static void changeFirst(int[] values) {
        values[0] = 99;
    }

    static void replaceArray(int[] values) {
        values = new int[] {500};
    }

    static int countPositive(int... values) {
        int count = 0;
        for (int value : values) {
            if (value > 0) {
                count++;
            }
        }
        return count;
    }

    static void verify(boolean ok, String label) {
        if (!ok) {
            throw new AssertionError(label);
        }
    }

    public static void main(String[] args) {
        verify(add(3, 4) == 7, "integer overload");
        verify(add(1.5, 2.25) == 3.75, "double overload");
        verify(describe("devices", 3).equals("devices: 3"), "return value");
        verify(sum(new int[] {2, 4, 6}) == 12, "array parameter");
        verify(countPositive(-2, 0, 3, 7) == 2, "variable arguments");

        int number = 7;
        changeNumber(number);
        verify(number == 7, "primitive passed by value");

        int[] readings = {1, 2, 3};
        changeFirst(readings);
        verify(readings[0] == 99, "shared array mutated");
        replaceArray(readings);
        verify(readings[0] == 99, "caller reference unchanged");
        verify(sum(readings) == 104, "array still accessible");

        try {
            sum(null);
            throw new AssertionError("null input was accepted");
        } catch (IllegalArgumentException expected) {
            verify(expected.getMessage().contains("null"), "null error");
        }
        System.out.println("10 method checks passed");
        System.out.println(describe("readings", readings.length));
    }
}

From a terminal in the containing directory, compile with warnings enabled and execute the class:

javac -Xlint:all MethodLab.java
java MethodLab

The checked output on OpenJDK 21.0.12.1 was:

10 method checks passed
readings: 3

Ten checks cover integer and floating-point overloads, a returned string, a sum, varargs, primitive argument copying, shared array mutation, reference reassignment, continued array access, and null-input rejection. A failed verification throws AssertionError; the count is a test tally, not a software-quality benchmark. Java's assert keyword is different from the deliberate verify helper, because language assertions are normally disabled unless enabled by a runtime flag.

Mistakes to Avoid

  • Do not describe an object parameter as pass-by-reference. Java copies the reference value.
  • Do not overload methods solely by changing their return types. The parameter list must distinguish them.
  • Do not assume static and instance methods are interchangeable; instance behavior requires an object.
  • Do not assume normal integer addition reports overflow. Use explicit checks when overflow matters.
  • Do not treat a passing example as proof of correctness for all inputs, threads, or production workloads.

Knowledge Check

  • Why does changing a primitive parameter not update the caller's integer? The callee receives a value copy.
  • Why can a method mutate the caller's array? Two copied references can identify the same array object.
  • What identifies Java overloads? Their method names together with parameter types; return type alone is insufficient.
  • How do callers handle a result? Store, pass, or evaluate the returned value rather than relying only on printed output.

Elementary Conclusion

A Java method is a reusable instruction with a name and clear inputs. The method can calculate a result and give it back through return. Several methods can use the same name as long as their parameter lists meaningfully differ. When a method receives a number, changing its local copy leaves the original alone. When it receives an array, it can change the shared array's elements. Those rules make larger programs easier to understand, reuse, and test.
