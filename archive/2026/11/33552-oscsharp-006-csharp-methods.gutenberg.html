A C# method is a named block of behavior that can accept parameters, calculate a result, and return control to the caller. Methods make larger .NET programs easier to organize because a validated operation can be reused without duplicating its statements. OSC#.006 covers return types, method overloading, named and optional arguments, and the important distinction between ordinary argument copies and the ref or out modifiers.

The lesson follows OSC#.005: C# Control Flow. Earlier units cover strings, operators, variables and types, and the .NET SDK. The Microsoft C# programming guide defines method syntax and return semantics.

Method Declarations and Return Values

A declaration such as private static int Add(int left, int right) says the method is private to its containing type, belongs to the type rather than an instance, receives two integers, and returns an integer. Parameter names identify the values locally. The return statement transfers a result to the caller, while a void method does not return a value. A method that returns a non-void type must supply a compatible value along its normal completion paths.

A method's overload signature identifies its name and relevant parameter types and passing modes. Changing only the result type does not create a separate overload. The two Add methods in the exercise accept either integers or doubles. The compiler selects an applicable overload according to argument types and language conversion rules, not simply the way the result will be printed.

Optional, Named, and Variable-Length Arguments

The method Label(string kind, int count = 1) provides a default value when a caller omits count. Named arguments allow Label(count: 3, kind: "switch") to identify parameters explicitly. The params int[] form accepts a normal integer array or several separate integer arguments, which the method receives as an array. For easy-to-maintain APIs, defaults should be predictable and overload lists should avoid ambiguous conversions.

The Microsoft references for named and optional arguments and parameter modifiers document the exact syntax and restrictions.

Pass-by-Value, ref, and out

C# passes arguments by value unless a supported modifier requests reference passing. For an ordinary integer parameter, reassignment changes only the local copy. A reference-type argument also passes its reference value by value, so the callee may modify the referenced object's contents without being able to reassign the caller's variable. The ref modifier instead allows the method to work with the caller's variable itself. The example's Increment(ref number) changes the caller's number from 7 to 8.

out provides an output parameter, commonly used by Try-style parsing methods. The caller need not initialize an out variable beforehand, but the method must assign it before a normal return. The demonstration validates a fictional wattage text field using int.TryParse, followed by a deliberately narrow range check. The resulting 0 to 10,000 teaching range is not an electrical safety threshold or manufacturer specification.

Complete Self-Contained C# Exercise

Create a console project with an available supported .NET SDK, replace its Program.cs contents with the code below, then run it locally. The sample has no network requests, external packages, privileged commands, or genuine telemetry inputs. It uses checked integer arithmetic to make overflow throw an exception rather than silently wrap.

using System;

internal static class MethodLab
{
    private static int checks;

    private static int Add(int left, int right) => checked(left + right);
    private static double Add(double left, double right) => left + right;

    private static string Label(string kind, int count = 1)
        => $"{kind}: {count}";

    private static void Increment(ref int value)
    {
        value++;
    }

    private static bool TryReadWattage(string text, out int watts)
    {
        if (!int.TryParse(text, out watts))
            return false;
        return watts is >= 0 and <= 10000;
    }

    private static int Sum(params int[] values)
    {
        ArgumentNullException.ThrowIfNull(values);
        int total = 0;
        foreach (int value in values)
            total = checked(total + value);
        return total;
    }

    private static void Check(bool condition, string label)
    {
        if (!condition)
            throw new InvalidOperationException(label);
        checks++;
    }

    public static void Main()
    {
        Check(Add(3, 5) == 8, "integer overload");
        Check(Add(2.5, 1.5) == 4.0, "double overload");
        Check(Label("rack") == "rack: 1", "default argument");
        Check(Label("rack", 2) == "rack: 2", "explicit argument");
        Check(Label(count: 3, kind: "switch") == "switch: 3", "named arguments");

        int number = 7;
        Increment(ref number);
        Check(number == 8, "ref updates caller variable");

        Check(TryReadWattage("650", out int watts) && watts == 650, "valid out");
        Check(!TryReadWattage("bad", out int invalid) && invalid == 0, "invalid text");
        Check(!TryReadWattage("-1", out int negative) && negative == -1, "negative");
        Check(!TryReadWattage("10001", out int above) && above == 10001, "over range");

        Check(Sum() == 0, "empty params");
        Check(Sum(1, 2, 3) == 6, "several params");
        Check(Sum(new[] { 4, 5 }) == 9, "array params");
        Check(Add(0, 0) == 0, "zero addition");

        bool nullRejected = false;
        try { Sum(null!); }
        catch (ArgumentNullException) { nullRejected = true; }
        Check(nullRejected, "null array rejected");

        bool overflowCaught = false;
        try { Add(int.MaxValue, 1); }
        catch (OverflowException) { overflowCaught = true; }
        Check(overflowCaught, "checked overflow");

        Check(Label("rack", 0) == "rack: 0", "zero count");
        Check(Label(kind: "router", count: 2) == "router: 2", "named order");

        Console.WriteLine($"{checks} method checks passed");
        Console.WriteLine(Label("devices", 3));
    }
}

Frequent Errors and Limitations

  • Assuming different return types alone define overloads. C# overload resolution depends on parameter signatures.
  • Treating ref and out as interchangeable. They have distinct initialization and assignment rules.
  • Assuming params automatically rejects a null array. Input validation remains necessary.
  • Using an unchecked integer sum when overflow must be reported.
  • Mistaking an educational range check for a production equipment operating limit.

Knowledge Check

  • What is returned by Add(3, 5)? The integer 8.
  • Can two methods differ only by return type? No.
  • Which modifier permits updating a caller's initialized local variable? ref.
  • Which modifier commonly supplies a parsed result? out.
  • What does params enable? An array parameter that callers can supply as separate arguments.

Elementary Conclusion

A C# method gives a reusable operation a clear name and contract. Parameters carry inputs, return statements produce results, and overloads allow one method name to support different parameter types. Named and optional arguments make call sites easier to read, while ref and out provide controlled access to caller variables. Validating inputs and checking arithmetic help keep reusable methods predictable.
