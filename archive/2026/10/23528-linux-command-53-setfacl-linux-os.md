<!-- wp:paragraph --><p><strong><code>setfacl</code> modifies Linux Access Control Lists so you can grant or remove permissions for specific users and groups without changing a file’s owner or relying only on the traditional owner/group/other model.</strong> It is the direct companion to <a href="https://bitcoinversus.tech/2026/10/10/linux-command-52-getfacl-linux-os/">Linux Command #52 – getfacl</a>, which reads ACLs.</p><!-- /wp:paragraph -->
<!-- wp:heading --><h2>What setfacl changes</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p>Traditional Linux permissions give one set of permissions to the owner, one to the owning group, and one to everyone else. ACLs add finer-grained entries. With <code>setfacl</code>, you can give one additional user read access, grant a project group write access, create inherited defaults on a directory, or remove extended ACL entries later.</p><!-- /wp:paragraph -->

Free-software screenshot via Wikimedia Commons.</em></figcaption></figure><!-- /wp:image -->
<!-- wp:paragraph --><p>The Linux <code>setfacl(1)</code> manual defines <code>-m</code> as modify, <code>-x</code> as remove, <code>-b</code> as remove all extended entries, and <code>-d</code> as applying operations to a directory’s default ACL. The file owner or a process with the required privilege can modify the ACL.</p><!-- /wp:paragraph -->

<!-- wp:heading --><h2>Grant a named user access</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p>To give a user named Alice read access to <code>report.txt</code>, run <code>setfacl -m u:alice:r report.txt</code>. The <code>u:</code> field identifies a user entry, <code>alice</code> is the account name, and <code>r</code> is the permission being granted.</p><!-- /wp:paragraph -->
<!-- wp:paragraph --><p>To grant read and write access instead, use <code>setfacl -m u:alice:rw report.txt</code>. Verify the result with <code>getfacl report.txt</code>. The new named-user entry should appear separately from <code>user::</code>, which represents the file owner.</p><!-- /wp:paragraph -->
<!-- wp:heading --><h2>Grant a named group access</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p>A named group uses the <code>g:</code> form. For example, <code>setfacl -m g:developers:rwx project</code> grants the <code>developers</code> group read, write, and execute permissions on the directory itself. Remember that directory execute permission means search/traverse permission; it is required to enter or access objects through that directory.</p><!-- /wp:paragraph -->
<!-- wp:paragraph --><p>This is where ACLs extend the ideas from <a href="https://bitcoinversus.tech/2026/10/10/linux-command-50-chmod-linux-os/">Linux Command #50 – chmod</a>. <code>chmod</code> remains the normal tool for owner/group/other mode bits, while <code>setfacl</code> is useful when the access model needs specific additional users or groups.</p><!-- /wp:paragraph -->
<!-- wp:heading --><h2>The ACL mask can limit effective permissions</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p>Extended ACLs include an effective-rights mask. The mask limits the permissions available to named users, the owning group, and named groups. That means a named entry can contain <code>rwx</code> while the effective access is smaller because the mask is more restrictive.</p><!-- /wp:paragraph -->
<!-- wp:paragraph --><p>By default, <code>setfacl</code> recalculates the mask when needed. The <code>-n</code> or <code>--no-mask</code> option suppresses that recalculation. Do not use <code>-n</code> casually; a stale mask is a common reason an ACL looks correct but does not grant the access an administrator expected.</p><!-- /wp:paragraph -->

<!-- wp:heading --><h2>Remove one ACL entry</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p>Use <code>-x</code> to remove a specific named entry. For example, <code>setfacl -x u:alice report.txt</code> removes Alice’s named-user ACL entry. When removing an entry, you identify the entry but do not include a permission field.</p><!-- /wp:paragraph -->
<!-- wp:paragraph --><p>For a named group, the equivalent form is <code>setfacl -x g:developers project</code>. Always verify with <code>getfacl</code> afterward instead of assuming the command produced the intended ACL.</p><!-- /wp:paragraph -->
<!-- wp:heading --><h2>Remove all extended ACL entries</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p><code>setfacl -b FILE</code> removes all extended ACL entries while retaining the base owner, group, and other entries. This is useful when returning a file to the ordinary permission model, but it is broader than deleting one named user or group entry, so inspect the ACL before using it on production data.</p><!-- /wp:paragraph -->
<!-- wp:heading --><h2>Create default ACLs on directories</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p>Default ACLs act as an inheritance template for newly created objects inside a directory. For example, <code>setfacl -d -m g:developers:rwx shared</code> adds a default entry for the <code>developers</code> group to the <code>shared</code> directory.</p><!-- /wp:paragraph -->
<!-- wp:paragraph --><p>This does not rewrite every existing file under the directory. It affects the ACL inherited by newly created children. To inspect the directory’s defaults, use <code>getfacl -d shared</code>. This also connects directly to <a href="https://bitcoinversus.tech/2026/10/10/linux-command-51-umask-linux-os/">Linux Command #51 – umask</a>: default ACLs participate in determining the final permissions of new files and directories.</p><!-- /wp:paragraph -->
<!-- wp:shortcode -->[tweet https://twitter.com/Rajeshstwt/status/2071627636246474839]<!-- /wp:shortcode -->
<!-- wp:heading --><h2>Recursive ACL changes</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p><code>setfacl -R -m g:developers:rX project</code> applies a group ACL recursively. The capital <code>X</code> is useful in recursive permission work because it grants execute only to directories or to files that already have execute permission for some user. That helps avoid turning ordinary data files into executable files simply because a recursive rule was applied.</p><!-- /wp:paragraph -->
<!-- wp:paragraph --><p>Recursive changes can affect thousands of objects very quickly. Test the exact command on a disposable tree first, capture the current ACLs when rollback matters, and avoid experimenting against system directories.</p><!-- /wp:paragraph -->
<!-- wp:heading --><h2>Back up and restore ACLs</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p>The output from <code>getfacl</code> can be used as input to <code>setfacl</code>. For a directory tree, administrators can create a permissions backup with a recursive <code>getfacl</code> command and restore it later using <code>setfacl --restore=FILE</code>. This is useful before large ACL migrations because the backup can preserve more than a simple list of mode bits.</p><!-- /wp:paragraph -->
<!-- wp:heading --><h2>Useful setfacl commands</h2><!-- /wp:heading -->
<!-- wp:list --><ul><li><code>setfacl -m u:alice:r FILE</code> — give Alice read access.</li><li><code>setfacl -m g:developers:rw FILE</code> — give the developers group read/write access.</li><li><code>setfacl -x u:alice FILE</code> — remove Alice’s named-user entry.</li><li><code>setfacl -b FILE</code> — remove all extended ACL entries.</li><li><code>setfacl -k DIRECTORY</code> — remove the directory’s default ACL.</li><li><code>setfacl -d -m g:developers:rwx DIRECTORY</code> — add a default group ACL.</li><li><code>setfacl -R -m g:developers:rX DIRECTORY</code> — modify ACLs recursively using conditional execute.</li><li><code>setfacl -m m::rx FILE</code> — explicitly set the effective-rights mask.</li></ul><!-- /wp:list -->
<!-- wp:heading --><h2>Troubleshooting checklist</h2><!-- /wp:heading -->
<!-- wp:list {"ordered":true} --><ol><li>Run <code>getfacl TARGET</code> before changing anything.</li><li>Confirm the correct user or group name with <code>getent</code> or <code>id</code>.</li><li>Apply the smallest ACL change needed.</li><li>Run <code>getfacl TARGET</code> again and inspect the mask and effective rights.</li><li>Check execute/search permission on every parent directory if access still fails.</li><li>Remember that ACLs do not change file ownership; use <code>chown</code> when ownership itself is wrong.</li><li>Test access as the affected user when possible instead of relying only on the ACL listing.</li></ol><!-- /wp:list -->
<!-- wp:heading --><h2>Practice lab</h2><!-- /wp:heading -->
<!-- wp:list {"ordered":true} --><ol><li>Create a disposable directory named <code>acl-lab</code> and a file inside it.</li><li>Run <code>getfacl</code> on both objects and save the initial output.</li><li>Add a named-user read entry to the file with <code>setfacl -m</code>.</li><li>Add a named-group read/write entry to the directory.</li><li>Inspect the ACL mask after each modification.</li><li>Create a default ACL on the directory, then create a new file inside it and compare the inherited ACL.</li><li>Remove only the named-user entry with <code>-x</code>.</li><li>Remove the extended ACLs from the disposable file with <code>-b</code> and verify the result.</li></ol><!-- /wp:list -->

<!-- wp:heading --><h2>Answer guide</h2><!-- /wp:heading -->
<!-- wp:list {"ordered":true} --><ol><li>It modifies or adds ACL entries.</li><li>Use <code>setfacl -x u:USERNAME FILE</code>.</li><li>It caps the effective permissions of named users, the owning group, and named groups.</li><li>It provides ACL entries that newly created children can inherit.</li><li>All extended ACL entries, while retaining the base owner, group, and other entries.</li><li><code>X</code> adds execute only to directories or files already executable for some user, reducing the chance of making ordinary files executable during a recursive operation.</li><li><code>getfacl</code>.</li></ol><!-- /wp:list -->
<!-- wp:heading --><h2>Key takeaway</h2><!-- /wp:heading -->
<!-- wp:paragraph --><p><strong><code>setfacl</code> is the write side of Linux ACL administration.</strong> Use it when ordinary mode bits are too coarse, make the smallest targeted change possible, and verify every result with <code>getfacl</code>—especially the ACL mask and default entries.</p><!-- /wp:paragraph -->
