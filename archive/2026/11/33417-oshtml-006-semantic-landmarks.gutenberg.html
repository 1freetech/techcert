Semantic HTML uses elements whose names describe the role of their content. A <nav> identifies navigation, <main> identifies primary page content, and <article> identifies a self-contained composition. The meaningful structure helps browsers, assistive technology, and other software interpret a document beyond its visual layout. Accurate markup does not guarantee accessibility by itself, but it establishes a dependable foundation for headings, landmarks, and keyboard navigation.

The earlier HTML tables tutorial explained how meaningful headers connect tabular data. Related references cover accessible forms, HTML attributes, element nesting, and document structure. The current unit focuses specifically on page regions and landmarks, using the W3C WAI page regions tutorial.

Elementary Overview

Imagine walking into a school. Signs show where the entrance, classrooms, library, and office are located. Semantic HTML gives similar signs to a webpage. It tells software which area holds the site menu, which area contains the main story, and which material is only additional reading. People can still see the page without those signs, but meaningful labels make moving around a complex page easier for many visitors.

Learning Objectives

  • Select appropriate semantic elements for major page regions and repeated content.
  • Explain what main, nav, and named section landmarks mean to assistive technology.
  • Distinguish site-wide headers and footers from those nested inside an article.
  • Use headings, IDs, and accessible names without adding redundant ARIA roles.
  • Run a complete example and inspect 20 focused structural checks.

Site Header, Navigation, and Main Content

A top-level <header> generally contains a site's identity and introductory links. When not nested inside a sectioning element, the header usually supplies the banner landmark. A <nav> represents a major collection of navigation links and supplies a navigation landmark. Multiple navigation menus are permitted, but meaningful names such as aria-label="Primary navigation" help distinguish them. Routine links inside article paragraphs do not each need a separate nav element.

A visible <main> contains content unique to the current page. An ordinary document should have one active main region, rather than multiple competing primary regions. The MDN main element reference and W3C landmark guidance explain the associated accessibility behavior. A skip link at the start of the body can point to the main region, allowing keyboard visitors to bypass repeated navigation.

Article, Section, and Aside

<article> represents content that can stand alone, such as a report or blog post. A <section> groups related material around a theme, normally with a descriptive heading. A section becomes a named region landmark when it has an accessible name, for example through aria-labelledby referencing an existing heading ID. Adding section elements merely for spacing does not make a document more semantic; use CSS and neutral containers where no meaningful section exists.

<aside> contains complementary information, such as a glossary or related explanation. Its contextual relationship to the main content matters more than whether CSS places it visually to the left or right. The MDN HTML elements reference defines these elements, while the W3C H101 technique explains how native semantic elements identify page regions.

Headers and Footers Change Meaning When Nested

A page can have more than one <header> or <footer>. At the site level, a header usually maps to banner and a footer to contentinfo. Headers or footers placed inside an article or section normally become ordinary introductory or closing content rather than extra banner or contentinfo landmarks. A nested article footer may contain author notes, while the site footer may contain contact or legal information. The MDN header documentation describes those context-sensitive semantics.

Complete Semantic HTML Example

Save the following standalone file as semantic-page.html. The example presents a fictional equipment report with site navigation, a unique main landmark, two titled sections, a complementary glossary, and separate site and article footers. No external CSS or JavaScript dependencies are needed:

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Lab Notes | Example Equipment Report</title>
</head>
<body>
  <a href="#content">Skip to main content</a>
  <header>
    <p>Lab Notes</p>
    <nav aria-label="Primary navigation">
      <ul>
        <li><a href="#report">Report</a></li>
        <li><a href="#glossary">Glossary</a></li>
      </ul>
    </nav>
  </header>
  <main id="content">
    <article id="report" aria-labelledby="report-title">
      <header>
        <h1 id="report-title">Example Equipment Report</h1>
      </header>
      <section aria-labelledby="method-title">
        <h2 id="method-title">Method</h2>
        <p>Three invented devices are reviewed as a training exercise.</p>
      </section>
      <section aria-labelledby="findings-title">
        <h2 id="findings-title">Findings</h2>
        <p>No live equipment was measured.</p>
      </section>
      <footer><p>Example prepared for learning only.</p></footer>
    </article>
  </main>
  <aside id="glossary" aria-labelledby="glossary-title">
    <h2 id="glossary-title">Glossary</h2>
    <p>A landmark identifies a major region of a page.</p>
  </aside>
  <footer><p>Lab Notes educational example.</p></footer>
</body>
</html>

Open the HTML file directly in a browser to inspect its source order and link targets. The Skip to main content link leads to the region with ID content; the navigation links lead to the report and glossary. The visible headings identify those areas. An aria-labelledby value must match an existing ID, or its intended name may not be exposed correctly.

Structural Tests and Accessibility Limits

A focused Python parser check of the exact sample passed 20 structural assertions. The checks covered the HTML doctype, English document language, UTF-8 metadata, viewport declaration, one main element, a named navigation region, article and aside presence, heading count, distinct IDs, valid fragment links, named sections, and the skip-link target. No browser-specific visual measurements or real hardware data are involved.

Parser checks are not equivalent to full HTML conformance validation, keyboard testing, or screen-reader evaluation. A reliable review should also use the Nu HTML Checker for standards conformance, a keyboard-only walkthrough, accessibility-tree inspection, and representative assistive technology where available. Semantic landmarks help identify regions, but they do not automatically fix unreadable text, inaccessible interaction controls, incorrect headings, or poor visual contrast.

Common Mistakes

  • Replacing every div with section, even when no meaningful section exists.
  • Putting multiple active main regions on one ordinary page.
  • Adding redundant role="navigation" to native nav without a specific need.
  • Using aria-labelledby values with no matching heading ID.
  • Assuming a landmark automatically guarantees keyboard or screen-reader usability.

Knowledge Check

  • Which element should contain the page's unique primary material? main.
  • Why label multiple navigation regions? Accessible names distinguish their purposes.
  • Does a header inside an article create another banner landmark? Normally no.
  • Why is an untitled section not necessarily a landmark? A section needs an accessible name to expose a region landmark.

Elementary Conclusion

Semantic HTML gives each major webpage area a useful name. Navigation links help people move through the site, the main region holds the central information, and sections and side notes organize related material. Good names and headings make the structure easier to understand. Testing remains important because meaningful tags alone cannot make every page accessible.
